# Guidance research and maintenance

Research date: 2026-10-17. Coverage: all 38 canonical model classes, including
12 healthy classes. The original ten entries were rewritten and 28 were added.
This is AI-authored synthesis of the sources below, not an independent review
or endorsement by an agronomist or any source organization. Bangla guidance is
an AI-authored translation/adaptation and needs fluent agricultural review before
being presented as professionally reviewed advice.

## Scope and safety

- A model result is a suggestion, not a confirmed diagnosis. Similar-looking
  diseases, nutrient problems and chemical injury may require laboratory testing.
- A healthy leaf image does not certify the whole plant, field or planting stock.
- Cultural management comes first. No universal pesticide, dose or spray calendar
  is prescribed. Any chemical use requires current local crop/disease registration,
  label directions, protective equipment, re-entry and preharvest intervals, and
  local resistance-management advice. Source-specific US registrations must not
  be assumed valid in Bangladesh or another jurisdiction.
- Viruses and HLB have no curative spray; established Esca wood infection is not
  cured by foliar fungicides. HLB requires local plant-health/quarantine advice.
- Corn leaf stripping and routine potato defoliation are not recommended.
  Late-blight advice calls for prompt confirmation and locally directed infected
  plant/haulm management, rather than trimming a few leaves.
- Healthy-care references cover the crop, not proof that the image classifier can
  diagnose every disorder of that crop. The corn care reference concerns sweet
  corn; no sweet-corn-specific spacing or fertilizer rates are generalized here.
- Regional disease severity and product efficacy vary. The grape Isariopsis
  advice combines NC State identification with Kentucky's emphasis on assessing
  whether minor leaf spots warrant intervention. The Florida target-spot source
  is not a claim that its fungicide program applies globally.

## Updating the catalog

1. Edit [the canonical English catalog](../android-app-kotlin/app/src/main/assets/diseases.xml)
   and [its Bangla counterpart](../android-app-kotlin/app/src/main/assets/diseases-bn.xml).
   Keep names compatible with the existing display-name keys. Do not change model
   label order or model keys to correct spelling. HLB lookup accepts the historical
   misspelling so existing names still resolve.
2. Keep a source URL with each English entry and update this audit when advice
   changes. Recheck regional relevance and current source recommendations.
3. Synchronize the deployment copy with PowerShell from the repository root:

   ```powershell
   Copy-Item android-app-kotlin/app/src/main/assets/diseases.xml backend-api/diseases.xml
   ```

   The backend Docker build uses only its own directory. Its packaged catalog
   must not depend on a sibling Android directory at runtime. The API parity test
   requires the two English files to match byte-for-byte.
4. Run the relevant checks from the repository root:

   ```powershell
   .\android-app-kotlin\gradlew.bat -p android-app-kotlin :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
   Push-Location backend-api
   .\.venv\Scripts\python.exe -m unittest discover -v
   Pop-Location
   ```

Coverage tests verify all 38 labels, unique complete entries, localized names,
English/Bangla catalog alignment, API response shape, unknown-label fallback and
cloud/offline content parity. They do not establish clinical/agronomic accuracy,
translation quality or model accuracy. Instrumentation tests additionally need a
connected Android device; compiling their APK is not executing them.
